# ConStellaration Plan → Implementation Gap Analysis

## Summary
- The strategy document calls for a hybrid physics/ML stack with multi-head surrogates, constraint-preserving PCFM/flow-matching generators, and advanced trust-region BO (including multi-objective hypervolume tracking) to cover Problems P1–P3.【F:docs/STRATEGY.md†L124-L185】
- The current codebase still revolves around low-dimensional 2D helical parameter baselines, simple feasibility penalties, and a single-target MLP surrogate, leaving most of the planned capabilities unimplemented or only partially scaffolded.【F:src/constelx/optim/baselines.py†L30-L168】【F:src/constelx/surrogate/train.py†L37-L101】
- Bridging the gap requires substantial work on surrogate learning, constraint extraction, higher-dimensional optimization, generative sampling, multi-objective tooling, and accompanying tests/docs to operationalize the proposed workflows.

## Existing Capabilities Snapshot
- Optimization baselines (trust-constr, ALM, NGOpt, FuRBO) operate on a 2D helical coefficient slice with coarse feasibility penalties, which is useful for smoke tests but insufficient for the full Fourier design space expected in the plan.【F:src/constelx/optim/baselines.py†L30-L123】【F:src/constelx/optim/furbo.py†L1-L200】
- Constraint extraction currently collapses evaluator outputs to a single feasibility flag/score, so there is no access to the per-metric inequality structure (mirror ratio, QI residual, magnetic well, etc.) that the plan assumes for ALM, PCFM, and BO constraints.【F:src/constelx/problems/constraints.py†L41-L68】
- Surrogate tooling consists of a basic single-output MLP trained on cached parquet data with an optional conflict-free gradient update, lacking the multi-head outputs, physics features, and uncertainty estimates required for the proposed pipeline.【F:src/constelx/surrogate/train.py†L37-L101】
- Data-driven priors exist (PCA + random forest + GMM/flow sampling) but stop short of the PCFM/PBFM conditioned generators envisioned for constraint-respecting sampling.【F:src/constelx/data/seeds_prior.py†L1-L186】

## Gap Analysis by Plan Component
### Cross-cutting infrastructure
1. **Multi-head surrogate modeling & feature engineering** – Need models that predict all task metrics (elongation, e_{L∇B}, ΔQI, mirror ratio, well depth, flux compression, aspect ratio, iota, triangularity) with uncertainty and physics-aware features as described in the plan.【F:docs/STRATEGY.md†L124-L130】 Current surrogate pipeline only outputs a single scalar with no engineered features or uncertainty, so new datasets, architectures, training loops, and evaluation scripts are required.【F:src/constelx/surrogate/train.py†L37-L101】
2. **Constraint extraction & normalization** – Plan assumes explicit constraint vectors for ALM/PCFM (e.g., bounds on mirror ratio, QI residual, magnetic well).【F:docs/STRATEGY.md†L134-L185】 The existing constraint helper needs extensions to parse evaluator metrics into normalized inequalities per problem and expose Jacobian-friendly forms for PCFM/BO usage.【F:src/constelx/problems/constraints.py†L41-L68】
3. **Higher-dimensional boundary parameterization** – Optimizers and agents must support the full Fourier coefficient set (including symmetry management, NFP sweeps, trust-region bounds) instead of the current 2D slice.【F:docs/STRATEGY.md†L124-L146】【F:src/constelx/optim/baselines.py†L30-L123】 This impacts boundary validation, logging, PCFM interfaces, and optimizer state persistence.
4. **Generative sampling with PCFM/PBFM** – The plan relies on PCFM-projected flow matching to draw feasible seeds for each benchmark.【F:docs/STRATEGY.md†L134-L166】 While PCFM correction exists, there is no end-to-end generator or training loop that couples surrogates with PCFM for sampling. Need to build training scripts (likely leveraging torch/jax), storage for learned flows, and agent hooks to integrate them.【F:src/constelx/agents/corrections/pcfm.py†L1-L200】【F:src/constelx/data/seeds_prior.py†L1-L186】
5. **Trust-region BO & NSGA-II/III** – FuRBO is present but limited to a single objective with scalarized feasibility signals; qEHVI, ε-constraint, and NSGA-II/III harnesses requested by the plan remain TODO.【F:docs/STRATEGY.md†L124-L185】【F:src/constelx/optim/furbo.py†L1-L200】 Need multi-output GP models per constraint, dynamic TR state, async batching, and objective-specific acquisition logic.
6. **Hypervolume tracking & Pareto tooling** – The plan targets hypervolume-based evaluation for P3, but the repo currently only offers scalarization and Pareto front extraction utilities without HV computation or qEHVI integration.【F:docs/STRATEGY.md†L170-L185】【F:src/constelx/optim/pareto.py†L1-L128】 Implement HV calculators, reference point management, and reporting hooks (CLI + artifact logging).
7. **Active learning & dataset augmentation** – Need pipelines that ingest VMEC outputs back into surrogate training (incremental parquet updates, re-training schedules, evaluation dashboards). Current tooling reads a static cache with no feedback loop.【F:docs/STRATEGY.md†L124-L130】【F:src/constelx/surrogate/train.py†L37-L101】

### Benchmark 1 (Geometric)
- Plan expects surrogate-driven PCFM sampling on the (A, \tilde\iota, \bar\delta) constraint manifold plus ALM/BO polishing.【F:docs/STRATEGY.md†L134-L148】 Missing pieces include differentiable estimators for A, \tilde\iota, \bar\delta, a constraint-aware sampler, and optimizers that operate over the required Fourier subset. Need to extend evaluator wrappers to expose these metrics cheaply, add autodiff-friendly surrogates, and provide CLI workflows for sampling + refinement.

### Benchmark 2 (Simple-to-build QI)
- Requires multi-objective surrogates (e_{L∇B}, ΔQI, Δ) and PCFM+PBFM hybrid generators, followed by local CMA-ES polishing with mode sparsity priors.【F:docs/STRATEGY.md†L152-L166】 Implementing this means: richer surrogate outputs, constraint-aware generator training, CMA-ES variants that operate in higher dimensions with sparsity regularization, and evaluator adapters delivering coil simplicity + QI metrics for training/gating. Current CMA-ES wrapper is 2D and penalty-based, so significant refactoring is necessary.【F:src/constelx/optim/baselines.py†L30-L123】

### Benchmark 3 (MHD-stable QI Pareto)
- Plan calls for qEHVI/ε-constraint BO, adaptive feasibility classifiers for vacuum well and flux compression, staged fidelity promotion, and hypervolume-based selection of Pareto points.【F:docs/STRATEGY.md†L170-L185】 Need to (a) expose W_MHD and ⟨χ∇r⟩ metrics via constraint extractors, (b) implement surrogate uncertainty + classifier workflows, (c) add multi-fidelity scheduling and memory of candidate fronts, and (d) extend submission packaging/artifacts to handle Pareto sets with HV reporting. None of these components exist today beyond scalarization helpers.【F:src/constelx/problems/constraints.py†L41-L68】【F:src/constelx/optim/pareto.py†L1-L128】

## Additional Infrastructure & Ops Work
- **Evaluator/VMEC integration** – Plan references hot-restart tokens, neighbor caches, and fidelity ladders; while hooks exist, need robust orchestration, cache invalidation, and configuration surfaces to support aggressive parallel searches envisioned in the plan.【F:docs/STRATEGY.md†L46-L55】
- **Testing & CI** – Each new optimizer/generator must ship unit tests (constraint normalization, surrogate accuracy) and integration tests (small-budget VMEC runs) per repository guidelines.【F:AGENTS.md†L55-L92】
- **Documentation & CLI UX** – Add tutorials covering surrogate training, PCFM/flow generators, BO workflows, and Pareto submission packaging aligned with the plan. Update CLI help and examples accordingly.【F:AGENTS.md†L111-L211】【F:docs/STRATEGY.md†L31-L67】
